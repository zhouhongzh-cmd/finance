# Phase 2 看板设计

> 关联基线: `docs/requirements_codex_v1.md`
> 说明: 本文档承接 Phase 2 看板的专题设计细节，不替代主需求书。

---

## 1. 目标

Phase 2 看板优化的目标固定为：

- 优先服务盘中决策效率
- 采用“轻量扩展数据层 + 多视图工作台”
- 继续使用 Streamlit
- 不做完整前端重构
- 不把研究型指标直接写成当前已实现能力

---

## 2. 默认形态

Phase 2 默认采用 3 个固定视图：

- `机会台`
- `复盘台`
- `系统台`

### 2.1 机会台

- 当前有效机会
- 期指期限结构板
- 转债候选池
- 快速筛选

### 2.2 复盘台

- 历史报警表
- 各策略报警统计
- 重复触发标的
- 近 7 日分布

### 2.3 系统台

- 数据源状态灯
- 降级状态
- 数据新鲜度
- 数据库与通知状态

---

## 3. 数据层范围

Phase 2 看板允许新增少量结构化快照，不继续只依赖 `alert_history.message` 文本。

最低要求如下：

- `futures_snapshot`
- `cb_snapshot`
- `source_health_snapshot`

用途约束：

- `futures_snapshot` 支撑期指期限结构板、排序和保证金占用展示
- `cb_snapshot` 支撑转债候选池与来源标识
- `source_health_snapshot` 支撑系统台状态灯和降级状态
- `alert_history` 继续保留为事件流，不替代快照层

---

## 4. 交互约束

如果进入 Phase 2，看板应按以下交互约束演进：

- 继续使用 Streamlit
- 使用 `tabs` 或等价的多视图切换方式实现工作台
- 首页优先使用卡片、矩阵和短表，而不是长页堆叠
- 颜色语义固定：
  - `CRITICAL` 红
  - `WARNING` 黄
  - `INFO` 蓝
  - 数据源 `OK` / `FALLBACK` / `FAILED` 使用绿 / 黄 / 红
- 移动端本阶段只保证可读，不单独设计专用布局

---

## 5. 验收参考事实

Phase 2 看板规划应至少引用并对齐以下已确认事实：

- 集成测试当前结果为 `16` 通过、`0` 失败、`0` 跳过
- 期指季月场景下可生成 `16` 个有效合约
- 现货指数新浪备源解析测试通过
- 真实环境下期指全链路可产出 `16` 条 live 数据
- 当前 live 结果曾触发 `9` 个期指信号

说明：

- 上述事实用于指导看板的数据展示重点
- 这些事实本身不等于看板 Phase 2 已实现
